## Why

ClickUp users had been asking for a Telegram integration for years, and the feature request just sat there. Teams already live in Telegram — so I built the bridge myself, and made it work for more than one tracker.

## What it does

- Subscribe to individual tasks and get updates in chat
- Read task descriptions without leaving Telegram
- Comment, reply and edit from the bot
- Your own changes don't echo back to you

## What I learned

The adapters layer was cheap only because it existed before any code. Asking for ClickUp, Wrike and Jira together rewrote the schemas, relations and models, and the Telegram layer was the only part that survived. Doing that after the first provider was already built would have spent the token budget on a rewrite.

The workflow still needed a person. Security comments didn't show up until I asked for a review in a fresh context. The product rules weren't in the API docs either: webhooks fire for the whole workspace, your own actions echo back to you, and Jira's webhooks don't behave like the other two. Docker came back as two applications until I said this is one app on one host.

I wouldn't skip the pauses between days. The adapters idea showed up away from the keyboard, and stopping at a phase was how I stayed inside the subscription limits. With unlimited tokens I might finish in three days. I wouldn't try to do it in one sitting.
