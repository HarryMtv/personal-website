## Why

Every new frontend I start wants the same pile: Vite 8, TanStack Router and Query, Zustand for UI state, shadcn, Vitest, Playwright, Docker, and the agent skills I already keep next to the code. Copy-pasting the last repo meant inheriting its product decisions. A scaffolder with zero runtime dependencies meant `npx` stays instant and the template stays mine.

## What it does

- `pnpm create frontstack my-app` — or `npm create` / `npx`
- Interactive prompts, or `--skills=claude,agents` / `--no-skills` for CI
- Copies a single-package template, restores npm-mangled dotfiles, substitutes the project name
- Wires agent skills as symlinks (junction / copy on Windows) and mirrors `CLAUDE.md` as `AGENTS.md`

The generated project is the unit under test: the suite runs the CLI into a temp dir and, when Node and Docker are available, exercises `pnpm check` and `pnpm build` on the output.

## What I learned

npm will eat your dotfiles. `.gitignore`, `.npmrc` and `.nvmrc` are stored as `_gitignore` / `_npmrc` / `_nvmrc` and renamed at copy time, because publish mangles them. Symlinks get the same treatment: `AGENTS.md` and the skills links are created after the copy, with a Windows junction and a plain-copy fallback, so the template itself never ships a symlink.

Zero runtime dependencies is a product decision, not a purity flex. A scaffolder people run via `npx` cannot afford a cold install of its own graph. The CLI is Node built-ins: `fs`, `path`, `readline`, `process`.

The template has to stay a project I would open tomorrow. This site is one of those repos — same Router, Query, Vite, Docker and skills layout. When the scaffold drifts from how I actually work, I feel it here first.
