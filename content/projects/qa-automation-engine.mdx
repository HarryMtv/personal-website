## Why

Autotests only stay useful if writing the next one is cheap. Wrike's main framework existed for that: one place to cover the product, from the UI down to the API, without a new harness for every suite.

## What it does

- Java, with Selenium driving the UI and Retrofit calling the API
- JUnit and TestNG run the suites
- The same tests run in more than one browser
- Allure collects the report
- 30,000+ tests live in the framework
- Code generation and dependency injection keep a new test short to write

</Columns>

## Where it sits

This is the Senior QA Automation Engineer work at Wrike, in Saint Petersburg, from June 2016 to September 2018. I took part in building the company's main test framework. The job of that framework was to make an autotest fast to write, and the stack above is what it was built on.
