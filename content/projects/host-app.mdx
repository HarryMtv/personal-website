## Why

The product is not one bundle. Reporting, Table View, Budgeting and the rest ship as their own apps, and a page should load the one the route is actually showing. Pulling every app up front would make the host pay for code the URL never asked for.

## What it does

- Each app is deployed on its own, and the version that went out is written to Consul
- The URL decides which app this route needs
- The host reads that version from Consul and downloads only its JS chunks
- The remote app is mounted with `createElement`, not copied into the host bundle

The host stays thin. It does not own the feature code. It resolves a route to an app, asks Consul which build is current, fetches the chunks for that build, and renders them. A new deploy is a new version in Consul, so the next load of that URL picks up the new chunks without a new host release.
