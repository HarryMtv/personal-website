# Igor Martynov — personal site

A personal website dressed as a desktop OS: terracotta tiled wallpaper, icon
rails, and one cream window per route titled `~/igor/<file>`. The repo also
works as a reference architecture — Feature-Sliced Design with CI-enforced
boundaries, zod-validated MDX content, a ports-and-adapters contact
transport, ADRs and a full test pyramid.

## Stack

React 19 · TypeScript · Vite 8 · TanStack Router + Query · Motion · Tailwind
CSS v4 · MDX + Shiki · zod · Zustand · Vitest · Playwright + axe ·
dependency-cruiser · Docker/nginx

## Scripts

```sh
pnpm install          # install
pnpm dev              # dev server
pnpm check            # typecheck + eslint + boundaries + vitest
pnpm test:e2e         # Playwright (desktop + mobile), incl. axe
pnpm build            # production build
pnpm lint:boundaries  # dependency-cruiser FSD rules alone
pnpm deps:graph       # regenerate docs/architecture/dependency-graph.mmd
```

## Layout

```
src/app        entry, router, thin routes, styles, providers
src/pages      one slice per window (about, projects, cv, contact, …)
src/widgets    desktop-shell, project-explorer, cv-document
src/features   filter-projects, send-contact-message, reading-toc, document-zoom
src/entities   profile, experience, project, post
src/shared     ui kit, lib hooks, config, mdx components
content/       projects/*.mdx, writing/*.mdx (zod-validated frontmatter)
docs/          architecture.md, adr/, dependency graph
```

Boundaries are enforced: a layer may only import from layers below it,
slices never import each other, cross-layer imports go through a slice's
`index.ts`, and `content/` is only reachable from `entities/*/api/**`. See
[docs/architecture.md](docs/architecture.md) and the
[ADRs](docs/adr/0001-feature-sliced-design.md).

## Authoring content

- **Add a project:** drop `content/projects/<slug>.mdx` with the validated
  frontmatter (`title`, `kind`, `tags`, `stack`, `order`, `hasCaseStudy`, …).
  The explorer, filters and case-study route pick it up automatically; write
  the MDX body when `hasCaseStudy: true`.
- **Add a post:** drop `content/writing/<slug>.mdx` (`title`, `summary`,
  `lead`, `readingMinutes`, `draft: false`, …). The TOC and heading ids are
  generated by the pipeline.

## Configuration

| Variable                  | Meaning                                        |
| ------------------------- | ---------------------------------------------- |
| `VITE_SITE_URL`           | Canonical URL (default `https://martynov.dev`) |
| `VITE_CONTACT_ENDPOINT`   | Web3Forms endpoint; empty ⇒ mailto fallback    |
| `VITE_CONTACT_ACCESS_KEY` | Web3Forms public access key                    |

See `.env.example`. The same values are Docker build `ARG`s.

## Deploy

```sh
docker build --build-arg VITE_SITE_URL=https://martynov.dev -t site .
docker run -p 8080:80 site
```

nginx serves the SPA with gzip, security headers and a real 404 for missing
`/cv/` files.
